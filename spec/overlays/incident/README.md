# `incident` overlay

**ITWS version:** 0.6.0-draft · **Minimum conformance tier:** `reviewed`

**Job:** establish what happened, who or what was affected, how responders restored service, what evidence supports causes or contributing factors, and which follow-ups result.

An `incident` separates timeline observations from causal interpretation.

## Load set

A writer, reviewer, or tool loads the following material for an `incident` document:

- The shared core in `spec/00-front-matter.md` through `spec/08-review-compliance-tooling.md`.
- The shared annexes in `spec/annexes/`.
- This directory: [reader.md](reader.md), [skeleton.md](skeleton.md), and [rules.md](rules.md).
- Shared overlay modules: none.

No other profile overlay applies to an `incident` document.

## Reader-test outcome

A publication-tier document measures this primary outcome (§8.3): reconstruct impact and timeline, distinguish confirmed evidence from interpretation, and state unresolved causes and follow-up actions.

## Owner review focus

The subject-matter owner focuses on timeline and evidence (§8.4).
